# Hardened router 1.2.1 release checks — October 25, 2026

This patch packages the hardening already merged in PRs [#10](https://github.com/Deirfgeiz/programscape-router/pull/10),
[#11](https://github.com/Deirfgeiz/programscape-router/pull/11) and
[#12](https://github.com/Deirfgeiz/programscape-router/pull/12), based on main
`69b349c62bf30e0e63d61450295bcd7de7d202c3`. It also handles the hosted MCP 1.1.0 explicit company selection contract,
with no changes to provider calls or balances. The optional config field `programscape.planId` selects the company
for both plan reads and reports, and the local date cache records that selection.

## Included hardening

- Patched Node trust baseline: exactly `22.23.4` or `24.22.1`, matching the reviewed package engines and CI matrix.
  Installers may treat engines as advisory. Users must update the runtime that launches their MCP client and restart
  the client; installing this package cannot patch an already running Node process.
- Patched dependency lock graph, including Body Parser 2.4.0 and Fast URI 3.1.9; Vitest 4.1.12 for development.
- CI actions pinned to reviewed commit hashes, with least-privilege job permissions.
- Explicit company selection: the router refuses a selection-required response before sending balances or replacing
  cached plan dates. Safe quoted names and plan ids tell the founder which id to put in config. Dates from another
  configured company are not used for ordering. A single-plan account still works without a configured id.

The package's dependency ranges permit these patched production dependencies for fresh consumer installs; this
release does not claim that its lockfile is enforced in downstream applications. Consumer package installation and
audit are checked separately from the repository lockfile.

## Publication checklist

Run on a supported patched runtime: frozen dependency installation, typecheck, all tests, build, production and full
dependency audits, and package smoke including the macOS test keychain. The smoke installs the tarball in a fresh
project, imports the public ESM API, checks shipped TypeScript declarations with `skipLibCheck: false`, runs the CLI,
and performs a set/read/list/status/remove round trip in the dedicated `programscape-router-ci` keychain service.
It never reads or writes the user's real provider key entries.

Require CI to pass on the final release commit before merge. Publish the validated tarball as a public npm package,
then independently check the registry version, `latest` tag, engine metadata, tarball integrity and a fresh public
consumer installation. Create `v1.2.1` and its GitHub release only after registry publication is confirmed.

The release PR and GitHub release record the actual checks and publication receipt. Package publication does not
upgrade existing installations or attest to any user's running Node version. The hosted Programscape MCP is a
separate service; its signed-in save/read verification is recorded separately.

## Local validation

On macOS arm64 with Node `v24.22.1` and npm `11.19.1`:

- `npm ci`, `npm run typecheck` and `npm run build` passed; the frozen graph audit reported zero vulnerabilities.
- All 399 tests in 19 files passed. Tests ran with loopback access so the OAuth callback binding checks could execute.
- `npm run smoke:pack -- --keychain` passed all consumer API/type/CLI checks and the real macOS test-service keychain
  set/read/list/status/remove round trip.
- The prepared tarball contained 80 files. A separate fresh consumer install of that artifact reported zero audit
  vulnerabilities and resolved Body Parser `2.4.0`, Fast URI `3.1.9` and MCP SDK `1.32.2` without overrides.
- The installed consumer exported version `1.2.1`, reported the reviewed Node engine metadata, and listed all eight
  providers with catalog reads disabled and no provider keys.
- `git diff --check` passed.

The new multi-company tests reproduced three failures before implementation: config rejected `planId`; an unselected
multi-plan response became an empty/unmapped plan; and a configured id reached neither read nor report. Regression
coverage also checks that selection refusal preserves the cached dates, names cannot inject terminal control
characters, changing company does not reuse earlier dates, and an Exa-only sync still requires a company choice even
though Exa has no live balance endpoint. Final validation and CI evidence are recorded in the release PR.
Two further regressions reproduced automatic-sync attempts and success labels crossing company selections, and
automatic selection refusal overwriting sync timestamps. Provider records now carry their configured plan id:
status, the six-hour wait and prior success timestamps only apply to the same selection, and an automatic selection
refusal writes no sync cache state.

The final cross-version transport correction makes an ambiguous `my_plan` response a standard MCP tool error with
structured company choices. Earlier installed routers refuse it before interpreting a plan; 1.2.1 reads its choices
and raises the dedicated company-selection guidance. The additional regression reproduced the missing typed error
through the actual SDK transport before correction, then passed with full sync-cache equality and no report calls.
The final 68 tests in the targeted sync/connection-lifecycle suites passed, along with typecheck/build and diff checks.
Required CI validates the complete 400-test suite; the complete local 399-test run above predates this additional
regression. No dependency changes followed the clean audit.
