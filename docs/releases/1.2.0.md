## Official-source checks

- https://docs.brightdata.com/proxy-networks/errorCatalog documents `client_10100` as a zone usage limit and
  `client_10020` as account suspension. Both stop further attempts for this router session; neither proves a
  measured free-credit balance. These codes remain source/fixture verified, not newly reproduced on a live account.
- The same page documents `Proxy-Status`, its Bright Data hop, received status and code prefix in `details`.
  The adapter previously missed this format. Three new adapter tests fail before the correction and pass after it.
  Router scenarios also check quota failover and recovery after a transient message-only failure.
- https://docs.brightdata.com/products/web-unlocker/error-codes states that an error message may be present without
  a machine-readable code. These answers now fail over rather than appearing successful.
- https://docs.brightdata.com/api-reference/account-management-api/Get_total_balance_through_API defines `balance`
  as available USD funds and explicitly provides no free-tier allowance, used/remaining credits or reset date.
  The router preserves the raw balance, does not add credit/prepayment or subtract pending costs speculatively,
  and keeps nonpositive readings informational. The earlier dashboard/API mismatch is not a conversion formula.
- https://docs.brightdata.com/api-reference/account-management-api/Add_a_Zone documents the zone and plan request.
  The existing SERP payload has a recorded successful live check from October 12. Web Unlocker creation remains
  covered by fixtures rather than a new live account mutation. Creation is opt-in, never part of ordinary routing;
  existing zone names can always be supplied manually.
